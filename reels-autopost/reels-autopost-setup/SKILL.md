# Мастер настройки автопубликации рилсов (Upload-Post)

Пошаговый онбординг: от «хочу автопостинг» до первой тестовой публикации. Веди пользователя по шагам, подтверждай каждый, не перескакивай. Пользователь нетехнический — точные ссылки, названия кнопок, простые слова.

## Шаг 0. Диагностика (молча, сам)

```bash
echo "$UPLOAD_POST_API_KEY" | wc -c; grep -c UPLOAD_POST_API_KEY .env 2>/dev/null
```

Если ключ уже есть — проверь его (Шаг 4) и переходи сразу к Шагу 5. Не гоняй пользователя по уже пройденным шагам.

## Шаг 1. Регистрация в сервисе

Скажи пользователю:
1. Открой **upload-post.com** → кнопка «Start for free» / «Sign up».
2. Зарегистрируйся (email или Google-аккаунт).
3. Тариф: для старта хватит Free (бесплатно, 10 загрузок/мес — но **без TikTok**). Для полного набора IG+TikTok+YT нужен **Basic $24/мес** (оплата картой, раздел Billing). Рекомендуй Basic, если TikTok нужен сразу.

Подожди подтверждения «зарегистрировался».

## Шаг 2. Подключение аккаунтов

1. В кабинете найди раздел **Profiles / Social Accounts** (иконка подключения).
2. По очереди нажми **Connect Instagram**, **Connect TikTok**, **Connect YouTube** и подтверди вход в каждом аккаунте (OAuth, пароли сервису не нужны).
3. **Важно про Instagram**: аккаунт должен быть «Автор» (Creator) или «Бизнес». Проверка в приложении: Настройки → Тип аккаунта и инструменты. «Личный» → переключить (бесплатно).
4. Профиль запомнит username (обычно = логину) — спроси, как он называется, запомни для `--user`.

## Шаг 3. Получение API-ключа

1. В кабинете: раздел **API Keys** → создать/скопировать ключ.
2. Пришли ключ мне в чат (это секрет: не публиковать, не коммитить в git).

## Шаг 4. Сохранение и проверка ключа (сам)

```bash
echo 'UPLOAD_POST_API_KEY=<ключ>' >> .env   # если ключа не было (или export в окружение)
# проверка: какие аккаунты подключены
KEY=$(grep '^UPLOAD_POST_API_KEY=' .env | cut -d= -f2)
curl -s "https://api.upload-post.com/api/uploadposts/users" -H "Authorization: Apikey $KEY"
```

Проверь: все три платформы в списке, `reauth_required: false`. Если платформы нет — вернись к Шагу 2. Покажи пользователю список подключённых аккаунтов.

## Шаг 5. Тест без публикации (сам)

```bash
python3 <путь_к_скиллу>/reels-publisher/scripts/publish_reel.py \
  --video https://example.com/test.mp4 --title "тест" --dry-run
```

`video_ok: true` + все три аккаунта в `accounts` → система готова.

## Шаг 6. Тестовая публикация (с пользователем)

1. Попроси прислать любое короткое вертикальное видео («которое не жалко») + текст.
2. Покажи превью (платформы, подпись, заголовок YouTube), получи «да».
3. Опубликуй через скилл **reels-publisher** (`--wait`), TikTok — режим draft по умолчанию (видео прилетит во входящие TikTok, допубликовать из приложения).
4. Доложи ссылки. Проверь вместе с пользователем, что посты видны в приложениях.

## Шаг 7. Финал — что рассказать пользователю

- Как публиковать дальше: «кидаешь видео + текст → я показываю превью → ты говоришь „да“ → выходит везде».
- Расписание: «опубликуй завтра в 19:00».
- Лимиты: TikTok 15/день, IG 50/день, YT 10/день.
- Прогрев новых аккаунтов: первые 2–4 недели 1–3 поста/день.
- Если у пользователя настроена очередь публикации по расписанию (cron) — упомянуть, что новые видео можно класть и туда.

## Питfalls

- Не путать онбординг с публикацией: ежедневный постинг — скилл `reels-publisher`, этот скилл — только первичная настройка и починка («перестало публиковаться» → Шаг 4, ищем reauth_required или просроченный ключ).
- TikTok на Free-тарифе не работает — если пользователь удивлён ошибкой TikTok, проверить тариф в Billing.
- Ключ — JWT с email внутри; не светить в логах/скриншотах, хранить только в env/файле `.env` вне git.
- Если пользователь прислал ключ не от Upload-Post (Blotato и т.п.) — стоп, сначала сверить сервис.
- После успешной настройки предложить сохранить в память агента: профиль Upload-Post, подключённые хэндлы, тариф.
